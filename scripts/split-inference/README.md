# Offline split-inference analysis

From the repository root, create a dedicated environment outside the repository and use a fresh output directory:

```bash
python3.12 -m venv ../split-analysis-venv
../split-analysis-venv/bin/python -m pip install -r scripts/split-inference/requirements.txt
../split-analysis-venv/bin/python -I -B scripts/split-inference/reproduce.py \
  --output ../split-analysis-output --publication mlsys-r22 --verify
```

Use Python 3.12.3 for byte-identical reproduction of the current A4 and R22 outputs, including numerical exports, with the pinned NumPy 1.26.4, SciPy 1.13.1 and Matplotlib 3.8.4 requirements. Confirm that `python3.12` resolves to that patch version before creating the environment. Python 3.10 was used for the historical source analysis; changes to standard-library summation and statistics can cause last-bit differences in repeat-uncertainty exports even when selection and measurement values agree. The reproduction command reports numerical or rendering differences when the environment changes. It reads the canonical compact inputs in `results/split-inference/data/inputs` plus the [R22 specifications and missing compact evidence](../../results/split-inference/publication-inputs/mlsys-r22/README.md), verifies their source bindings, and regenerates the broad numerical exports, 23 broad PDF/SVG/PNG figure families, gallery and table indices, captions, findings and methods. The default registered `mlsys-r22` profile additionally generates eight figures and 28 tables under `publications/mlsys-r22/` in the output directory. It uses no network, sensors, accelerators, models or datasets after dependency installation. It processes stored numerical observations; it does not reintegrate raw sensor traces or repeat a benchmark.

`--verify` runs the existing selection/aggregation/Pareto tests, an independent standard-library checker and a direct byte comparison of generated scientific artifacts with the published copies. Different plotting dependencies may change rendering bytes; a mismatch is reported rather than hidden. The independent checker verifies all 450 FPS cohorts, 1,350 energy repeats, 42 Full configurations, 204 Native/Generic pairs, 816 split/Full comparisons, all figure payloads, and the preservation of all 375 direct observations outside the A4 replacement cohort and 450 original quality selections. It also checks all 450 Pareto rows, the 21 model/setup groups, joint and runner-specific fronts, and the plotted coordinates. Front membership is recomputed from the current observations; quality remains visible and does not filter membership.

For numerical reproduction with Python alone, omit plotting dependencies and add `--numeric-only`. This generates the broad tables and every R22 numerical payload, CSV/JSON/Markdown/LaTeX table, manifest and publication index without importing Matplotlib or invoking LaTeX. It skips image rendering and the broad figure/report generation. Use a fresh output directory for each command:

```bash
../split-analysis-venv/bin/python -I -B scripts/split-inference/reproduce.py \
  --output ../split-analysis-r22-numeric --publication mlsys-r22 --numeric-only --verify
```

`--publication mlsys-r22` is explicit in these examples; omitting it produces the same registered profile in both full and numerical modes. Both modes require an empty or nonexistent output directory. Plot cache files are placed beside that output, outside the repository. The R22 [manifest](../../results/split-inference/publications/mlsys-r22/ASSET_MANIFEST.json), [all 36 assets](../../results/split-inference/publications/mlsys-r22/README.md), [figure gallery](../../results/split-inference/publications/mlsys-r22/figures/README.md) and [table index](../../results/split-inference/publications/mlsys-r22/tables/README.md) are generated by this one entry point.

R22's numerical 5% CPU-relative quality view admits 407 configurations and pairs 187 Native/Generic cuts in 21 equally weighted groups. The broad 450-row analysis and unfiltered Pareto population retain their existing rules. Scheduling, stage-cost and historical R10/THESIS20 evidence retain distinct cohorts. Profile verification checks the active 36-asset/37-occurrence inventory, selection and denominator identities, source-bound repeats, figure coordinates, all nine ridge folds and 151 predictions, and the separate 40/40/20-process scheduling studies. It also checks the compact R20 endpoint/workload/energy-window projections and compares all generated scientific files directly with the published profile.

The [reference differences](../../results/split-inference/publications/mlsys-r22/REFERENCE_DIFFERENCES.md) document the current-source vendor-table binding and the original YOLO26s/H8 b021 energy-repeat range added beyond the paper's incomplete extract. Frozen R22 labels describe asset correspondence; the manuscript and its original PDF bytes are not rewritten or used as render-byte targets.

`table3_fastest_deployments` selects the highest unrounded observed FPS split per model across all setups and both runners, and the highest FPS concrete Full across all hosts. `fastest_split_baselines` retains that same split UID and adds the highest FPS Full on its physical host. Both preserve energy from the exact throughput-selected configurations; missing energy never substitutes another FPS winner. `fastest_split_baseline_comparison` and `fastest_deployment_tradeoff` read those same selections. The former illustrates the denominator effect; the latter uses throughput and energy ratios against one common global Full UID. The old `table3_top2_native` keeps the separate historical method: two Native splits per model ranked by relative same-host speedup. Selection, denominator identity, exact ties, missing metrics and figure coordinates are covered by the targeted tests and independent checker.

The selection rules, including throughput maximization and energy minimization within each model/setup, are in [config.json](config.json). Scripts preserve the source calculation and rendering logic; the export changes relative data paths, extracts the unchanged quantile helper, and omits duplicate manuscript ZIPs, report matrices and output-hash registries. [Results and interpretation limits](../../results/split-inference/README.md) describe actual timed-work differences, quality losses, original flags and unresolved source limitations. Existing archive identifiers in the data are metadata, not dependencies on private files.

The analysis retains the selection, aggregation and Pareto rules of [Results revision 380dfa09](https://github.com/Keff789/onnx-splitpoint-results/tree/380dfa09aa6740acdc71908cb6e5dd5c8fc115ad/results/evaluation/paper_after_refresh16_20261013), with the current `deepx_native_a4_20261015` replacement cohort. Exactly 75 DeepX Native identities use 225 selected performance and 225 calibrated energy repeats; the remaining direct observations and all original quality selections are retained. The offline evaluator reads these compact inputs, independently of the [ONNX Splitpoint Tool sources](../../software/README.md).

## Current MLSys R30 publication profile

Install `scripts/split-inference/requirements-r30.txt` in a separate environment
and run:

```sh
python -I -B scripts/split-inference/reproduce.py --publication mlsys-r30 \
  --output ../mlsys-r30-output --verify
```

The profile regenerates the existing measurement tables and figures, the maintained
boundary illustration, the seven-model Weighted comparison and an additional
single-column YOLOv7 case figure. The wide YOLO view remains available.
`--numeric-only` omits image rendering. Unlike the frozen R22 render-byte gate,
R30 verification checks exact scientific CSV/JSON/TeX payloads while allowing
the documented common figure style. It also checks seven disjoint model folds,
187 eligible pairs in 21 groups, unchanged baseline selections, original R22
measurement coordinates and unchanged YOLO case values. The default R22 command
and its reference results are unchanged.

See [Weighted study](../supplementary-studies/rq2-weighted-20261020/README.md)
for original inputs, full-graph normalization, operation proxy version, fitting
objective and sensitivity checks. Generated assets are under
`publications/mlsys-r30` in the requested output directory.


## Deutsche Grafiken und Tabellen für die Dissertation

Mit dem R30-Profil lässt sich zusätzlich eine deutsche Ausgabe erzeugen:

```sh
python -I -B scripts/split-inference/reproduce.py \
  --publication mlsys-r30 --languages en de \
  --output ../split-auswertung-zweisprachig --verify
```

Dafür die Umgebung aus `requirements-r30.txt` verwenden und ein leeres
Ausgabeverzeichnis wählen. Die englische Ausgabe bleibt erhalten. Unter `de/`
stehen zusätzlich deutsche Grafiken als PDF/SVG/PNG und Tabellen als TeX/Markdown,
einschließlich der ergänzenden Split-Studien. Numerische CSV-/JSON-Daten,
Auswahlregeln und die Trennung der Messreihen bleiben unverändert.

Die [Anleitung zum deutschen Export](../dissertation/README.md) beschreibt auch
den schnelleren Aufruf aus bereits vorhandenen Ergebnissen, Tabellen ohne
Grafikrendering und die festen Übersetzungskataloge. Die
[deutsche Sammlung](../../publications/dissertation/de/README.md) enthält
58 Grafikfamilien und einen Tabellenindex. Das separate Energiemessungs-Tool
gehört nicht zu diesem Export.
